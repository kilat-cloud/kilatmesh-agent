# LAPORAN REBRAND — KilatMesh Agent (fork klien NetBird)

Tanggal: 2026-11-11 · Pelaksana: tim platform PT Kilat Cloud Indonesia
Repo: `kilatmesh-agent` (lokal, belum dipush ke mana pun)

## 1. Ringkasan

Fork ini mengambil **klien/agen** NetBird (lisensi BSD-3-Clause) dan
mengganti seluruh branding yang terlihat pengguna menjadi
**KilatMesh**. Komponen server (management/signal/relay/dashboard,
AGPLv3) **tidak** termasuk fork ini dan **tidak** dimodifikasi:
deployment menjalankan server upstream apa adanya (self-hosted).

| Versi dipin | **v0.82.1** (stabil terakhir saat fork dibuat) |

## 2. Yang di-rebrand (sebelum → sesudah)

### Identitas produk & CLI
- Root command: `Use: "netbird"` → `"kilatmesh"`; seluruh `Short`/`Long`/
  `Example`/pesan cetak di `client/cmd` (20 file): "NetBird …" →
  "KilatMesh …", contoh perintah `netbird up|service|debug|profile …` →
  `kilatmesh …`.
- `kilatmesh version` mencetak: `KilatMesh Agent 0.82.1`.
- Output status (`client/status`): `NetBird IP:` → `KilatMesh IP:`,
  `NetBird IPv6:` → `KilatMesh IPv6:`.
- Pesan error daemon di `client/server` (gate SSH/debug) dan perintah
  remediasi `ipcauth.UpCommand`: `netbird …` → `kilatmesh …`
  (mis. "sudo kilatmesh service install …", "kilatmesh debug bundle -U …").
- Teks EDE DNS forwarder: `netbird forwarder: …` → `kilatmesh forwarder: …`.
- Header yang ditulis agen ke `/etc/resolv.conf`:
  `# Generated by NetBird` → `# Generated by KilatMesh` (konstanta yang
  sama dipakai untuk deteksi, jadi tulis+deteksi konsisten).
- Prefix log wireguard-go: `[netbird] ` → `[kilatmesh] ` (6 file device).
- Link bantuan yang tadinya menunjuk `docs.netbird.io` kini menunjuk
  `https://kilat-cloud.com`.

### Service / daemon
- Nama service default: `netbird`/`Netbird` → **`kilatmesh`** (Linux
  systemd maupun Windows, `client/cmd/service.go`).
- DisplayName: `Netbird` → **`KilatMesh Agent`**.
- Description: `NetBird mesh network client` →
  `KilatMesh Agent - agen konektivitas sekolah PT Kilat Cloud Indonesia (mesh VPN berbasis WireGuard)`.
- Unit systemd klien diganti nama `release_files/systemd/netbird@.service`
  → **`kilatmesh@.service`**: Description KilatMesh Agent,
  `ExecStart=/usr/local/bin/kilatmesh service run --log-file /var/log/kilatmesh/client-%i.log
  --daemon-addr unix:///var/run/kilatmesh/%i.sock`,
  `EnvironmentFile=-/etc/default/kilatmesh`, semua `*Directory=kilatmesh`.
  (Unit `netbird-management.service`/`netbird-signal.service` adalah
  komponen server AGPL — tidak diubah, bukan bagian distribusi fork.)
- File penahan systemd-networkd: `99-netbird.conf` → `99-kilatmesh.conf`.
- Nama service fallback untuk pengumpulan journal di debug bundle:
  `netbird` → `kilatmesh` (`client/internal/debug`).

### Path & file default
- Konfigurasi: `/etc/netbird/` → `/etc/kilatmesh/`; state:
  `/var/lib/netbird/` → `/var/lib/kilatmesh/`; log: `/var/log/netbird/` →
  `/var/log/kilatmesh/`; FreeBSD: `/var/db/netbird/` → `/var/db/kilatmesh/`;
  Windows: `%PROGRAMDATA%\Netbird\` → `%PROGRAMDATA%\KilatMesh\`.
  Berlaku konsisten di `client/cmd/root.go`,
  `client/internal/profilemanager`, dan `client/configs`.
- Direktori konfigurasi per-pengguna: `~/.config/netbird` →
  `~/.config/kilatmesh` (dan padanan macOS).
- Socket daemon: `/var/run/netbird.sock` → `/var/run/kilatmesh.sock`;
  socket JSON: `netbird-http.sock` → `kilatmesh-http.sock`; direktori
  scan socket: `/var/run/netbird` → `/var/run/kilatmesh`; named pipe
  Windows: `npipe://netbird` → `npipe://kilatmesh`.
- File tangkapan daemon: `netbird.err`/`netbird.out` →
  `kilatmesh.err`/`kilatmesh.out`; nama berkas debug bundle:
  `netbird.debug.*.zip` → `kilatmesh.debug.*.zip`,
  `netbird.debug-file.` → `kilatmesh.debug-file.`.

### Objek OS lain yang terlihat admin
- nftables: tabel `netbird` → `kilatmesh`; chain `netbird-rt-fwd`,
  `netbird-acl-*`, `netbird-mangle-*`, dll. → prefix `kilatmesh-`
  (konstanta terpusat di `family_linux.go`/`manager_linux.go`).
- iptables: format nama rule `netbird-fwd-*`, `netbird-nat-*`,
  `netbird-prerouting-*` → `kilatmesh-*`.
- Tabel routing kustom: nama `netbird` → `kilatmesh`
  (`NetbirdVPNTableName`, ID tabel tidak berubah).
- Rule Windows Firewall (uspfilter): `Netbird` → `KilatMesh`.
- Nama user/context kubeconfig yang ditulis `kilatmesh kubernetes`:
  `netbird` → `kilatmesh`.
- Marker elevasi stdout: `netbird-elevated: applied` →
  `kilatmesh-elevated: applied` (konstanta tunggal, semua pemakai
  merujuk konstanta).
- Nama binary daemon yang dicari updater: `netbird`/`netbird.exe` →
  `kilatmesh`/`kilatmesh.exe`; nama di `.goreleaser.yaml` untuk semua
  build klien: `binary: netbird` → `binary: kilatmesh` (build server
  tidak disentuh); `client/manifest.xml`: deskripsi KilatMesh Agent.

### Endpoint default (nilai berubah, mekanisme tidak)
- `DefaultManagementURL`: `https://api.netbird.io:443` →
  **`https://mesh.kilat-cloud.com:443`**; `DefaultAdminURL` →
  `https://mesh.kilat-cloud.com:443`. Alasan: agen whitelabel tidak
  boleh diam-diam mendaftar ke cloud upstream bila operator lupa
  memberi URL. Mekanisme parsing/fallback tidak diubah, dan alur
  provisioning platform **selalu** mengisi `--management-url` /
  `NB_MANAGEMENT_URL` secara eksplisit, jadi nilai default ini hanya
  jaring pengaman. **Wajib dikonfirmasi** saat domain mesh produksi
  diputuskan (lihat §6).
- URL upload debug bundle default: `https://upload.debug.netbird.io`
  → `https://upload.debug.kilat-cloud.com` (placeholder di domain
  perusahaan; bundle debug sekolah tidak boleh terkirim ke layanan
  pihak ketiga secara default). Fitur upload sendiri tidak diubah.

### Dokumentasi repo
- `README.md` baru (Bahasa Indonesia): KilatMesh Agent, cara daftar
  sekolah, path penting, cara build, atribusi upstream. README
  upstream dipertahankan sebagai `README.upstream.md`.
- `UPSTREAM.md` baru: pin versi + kebijakan sinkronisasi.
- `NOTICE` baru: atribusi fork NetBird (BSD-3-Clause), modifikasi

## 3. Yang SENGAJA tidak diubah (batasan keras)

- **Modul Go & path impor** `github.com/netbirdio/netbird/...` —
  internal, tidak terlihat pengguna; menggantinya merusak build dan
  menyulitkan sinkronisasi upstream.
- **Protokol wire** ke management/signal/relay, format key &
  identitas peer, mekanisme URL management — kompatibilitas dengan
  server NetBird standar utuh.
- Konstanta protokol/kriptografi bersama: `netbird-ssh` (penanda
  protokol policy), domain separasi sertifikat
  `netbird-cert-challenge-v1`/`netbird-posture-cert-v1`,
  `refused@netbird.io` (tipe request kanal SSH), header IPC daemon
  `x-netbird-fwd-*`, label discovery `netbird-kubeapi-proxy`.
  Mengubahnya akan merusak interoperabilitas.
- Env var `NB_*`/`WT_*` — antarmuka operator yang sudah dipakai alur
  provisioning platform (mis. `NB_MANAGEMENT_URL`, `NB_SETUP_KEY`).
- Identifier kode (mis. `NetbirdVersion()`, `migrateToNetbird`,
  `tableNameNetbird`, `existingNetbirdRulesInChain`) dan mayoritas
  komentar kode yang menyebut proyek upstream — internal, dan
  mempertahankannya membuat rebase upstream murah.

## 4. Perintah build

```bash
source ~/.dev-env.sh
# Catatan VM ini: /tmp adalah tmpfs 512 MB, terlalu kecil untuk
# temp build Go proyek ini. Arahkan GOTMPDIR ke disk:
mkdir -p ~/.gotmp

cd client
GOTMPDIR=~/.gotmp CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build \
  -tags load_wgnt_from_rsrc \
  -ldflags "-s -w -X github.com/netbirdio/netbird/version.version=0.82.1" \
  -o ../dist/kilatmesh-linux-amd64 .

GOTMPDIR=~/.gotmp CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build \
  -tags load_wgnt_from_rsrc \
  -ldflags "-s -w -X github.com/netbirdio/netbird/version.version=0.82.1" \
  -o ../dist/kilatmesh.exe .
```

Tag dan ldflags sama seperti build klien resmi upstream di
`.goreleaser.yaml` (entrypoint `client/` = paket main yang sama
dengan binary service upstream). `dist/` ter-gitignore: binary
adalah artefak build, tidak masuk git.

SHA-256 (awal): linux `45f44a37421123b6…`, windows `bc7714baa24effe8…`

## 6. Sisa kemunculan "netbird" — klasifikasi jujur

Tidak ada lagi "netbird" pada permukaan yang terlihat pengguna akhir
(help, versi, service, path, nama file, objek firewall/routing,
header resolv.conf, pesan error/CLI). Yang tersisa, semuanya internal:

| Kategori | Contoh | Alasan aman |
|---|---|---|
| Path impor & nama modul Go (658 file merujuk) | `github.com/netbirdio/netbird/client/...` | Internal build; dilarang diganti oleh desain fork |
| Identifier & komentar kode (~ratusan baris) | `NetbirdVersion()`, `nbAgent`, komentar menyebut proyek upstream | Tidak pernah tampil ke pengguna; menjaga diff kecil untuk rebase |
| Konstanta protokol/kripto bersama server | `netbird-ssh`, `netbird-cert-challenge-v1`, `refused@netbird.io`, `x-netbird-fwd-*` | Mengubahnya merusak interoperabilitas dengan server upstream yang dijalankan apa adanya |
| Env var operator | `NB_MANAGEMENT_URL`, `NB_SETUP_KEY`, `NB_STATE_DIR` | Kontrak provisioning yang sudah berjalan |
| Telemetri internal | nama metrik `netbird_sync`, `netbird_peer_connection`, JSON key `netbirdIp` pada status internal | Kontrak metrik/format internal daemon↔UI; bukan branding pengguna |
| Label discovery k8s | `netbird-kubeapi-proxy` | Label yang dipasang komponen proxy upstream; klien hanya mencarinya |
| Identifier OS sempit | `"netbird"` sebagai SourceName token logon Windows (kolom 8 char), prefix-cek user-agent gRPC internal | Tidak tampil di UI mana pun |
| Komponen fase 2 | `client/ui` (systray "NetBird desktop client"), `client/android`, `client/ios`, installer `client/installer.nsis` & `client/netbird.wxs`, `release_files/install.sh` & skrip packaging lain | Di luar cakupan fase ini (agen headless); UI/installer di-rebrand saat fase packaging |

### Endpoint upstream yang masih dirujuk fitur opsional (bukan branding, tapi aliran data)
Kode updater/telemetri upstream masih menunjuk infrastruktur NetBird:
check update `https://pkgs.netbird.io/...`, kunci signing updater
`https://publickeys.netbird.io/...`, dan telemetri metrik
`https://ingest.netbird.io` (bila metrik diaktifkan). Ini **belum**
diubah karena mengubahnya berarti mengubah mekanisme update/telemetri
(di luar mandat rebrand) — tetapi **wajib diputuskan sebelum produksi**:
nonaktifkan update & metrik, atau arahkan ke infrastruktur Kilat
Cloud. Bila dibiarkan, updater pada Windows/macOS dapat mengganti
binary KilatMesh dengan binary upstream. Untuk agen headless
Linux/Windows yang dipasang via service, risiko praktisnya rendah,
tetapi keputusannya harus eksplisit, bukan bawaan.

   endpoint upload debug, dan kebijakan update/telemetri.

   rilis; diff rebrand dijaga dangkal agar murah.
